# knowbase-md

Текущая версия: **2.0.1**.

`knowbase-md` - простой сайт для публикации базы знаний из Markdown-файлов. Проект рассчитан на небольшие учебные материалы, инструкции и внутренние статьи, которые удобно хранить в папках и редактировать обычным текстовым редактором.

В репозиторий выкладывается только код сайта и документация. Рабочие статьи, изображения и другие медиафайлы лежат локально в `articles/` и не отправляются в GitHub.

## Возможности

- закладки и продолжение чтения без регистрации, с хранением в браузере;
- увеличение изображений, копирование кода, глоссарий и связанные статьи;
- блоки самопроверки и локальный HTML-генератор заданий;
- информационные блоки «Важно», «Осторожно», «Пример», «Совет» и вкладки с Markdown-содержимым;
- копирование ссылки на конкретный заголовок статьи;
- учебные маршруты из Markdown с пошаговыми переходами между категориями;
- публичные кнопки скачивания вложений;
- даты обновления статей и отдельная лента изменений;
- замечания с обязательными фамилией, именем и Telegram, закрытая страница администратора;
- проверка контента перед публикацией без изменения файлов;

- автоматическая сборка главной страницы по папкам внутри `articles/`;
- категории с названием, описанием и списком статей;
- отдельные страницы категорий с авторами, подгруппами статей и поиском внутри раздела;
- боковой блок на широких экранах: посетители за последние 24 часа и пять новых открытых статей;
- Markdown-рендеринг с таблицами, списками, блоками кода и оглавлением;
- подписи к отдельным изображениям через синтаксис `![Подпись](media/file.jpg)`;
- поддержка LaTeX-формул через MathJax;
- поиск по названиям, описаниям и тексту статей;
- авторы статей с отдельными страницами, описаниями, фото и списками материалов;
- редакторы статей из того же списка профилей, с отдельными списками редакторских работ;
- фиксированная нижняя навигация между соседними статьями раздела;
- сворачиваемое оглавление статьи;
- одиннадцать тем оформления; для семи доступны светлый и тёмный режимы, Hello Kitty, «548», Robo548 и «Миньоны» используют только светлый;
- простая парольная защита отдельных статей;
- единый футер, favicon и статические стили без сборщика фронтенда.

## Быстрый запуск

Требуется Python 3.12 или совместимая версия Python 3.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe main.py
```

По умолчанию сайт запускается на `http://localhost/`, если в `.env` указан `PORT=80`. Для локальной разработки удобнее поставить, например:

```env
HOST=127.0.0.1
PORT=8000
```

После этого сайт будет доступен по адресу `http://127.0.0.1:8000/`.

## Работа с контентом

Контент хранится в `articles/`. Каждая папка первого уровня становится разделом сайта. Внутри раздела можно хранить Markdown-статьи и папку `media/` с изображениями.

Минимальная структура раздела:

```text
articles/
  10-example/
    category.txt
    description.txt
    00-intro.md
    01-next-topic.md
    media/
      image.jpg
```

Подробнее: [docs/site-guide.md](docs/site-guide.md).

Первый запуск на чистом сервере: [Ubuntu 26.04, systemd, Nginx и HTTPS](docs/deploy-ubuntu-26.04.md). Инструкция использует отдельного системного пользователя и внутренний порт `8000`; Docker не требуется.

Инструкция администратора включает синтаксис информационных блоков и вкладок, создание маршрутов, проверку ссылок и обновление существующего сервиса на сервере. Для новых возможностей установите зависимости из `requirements.txt`; версия Python-Markdown остаётся прежней, добавляется PyMdown Extensions.

Маршруты создаются вручную в `learning-paths/<slug>.md`: первый `# Заголовок` задаёт название, а нумерованный список в разделе `## Шаги` — порядок ссылок на статьи. Список доступен на `/paths`, отдельный маршрут — на `/paths/<slug>`. Рабочие файлы маршрутов переносятся на сервер отдельно от Git, как статьи и профили авторов.

Новые форматы, настройка замечаний и генератор: [docs/reader-features.md](docs/reader-features.md).

Файл `announcement.md` тоже считается локальным контентом и игнорируется Git. Его можно создать рядом с `main.py`, чтобы показать объявление на главной странице конкретной установки сайта.

Профили авторов хранятся в `authors/` и тоже игнорируются Git. У статьи можно указать авторов служебным комментарием `<!-- authors: vdn, ivan-petrov -->` в начале Markdown-файла.

Редакторы указываются отдельно комментарием `<!-- editors: dps -->` и используют те же профили из `authors/`. На странице статьи они отображаются с фотографиями отдельным блоком под авторами, перед текстом. На странице профиля авторские статьи и статьи под редакцией перечисляются отдельно, с группировкой по категориям.

## Переменные окружения

Проект читает `.env` при запуске. Реальные пароли и серверные настройки не нужно коммитить.

Основные переменные:

```env
HOST=0.0.0.0
PORT=80
DATA_DIR=./data
ADMIN_PASSWORD=
ARTICLE_PASSWORD_10_EXAMPLE=change-me
```

Имя переменной для пароля строится из имени папки раздела: верхний регистр, все не-буквенно-цифровые символы заменяются на `_`.

`ADMIN_PASSWORD` включает приём замечаний и вход на `/admin/feedback`. Для публичного сервера задайте длинный уникальный пароль; пустое значение отключает эту функцию. Локальные тестовые пароли на сервер не переносите.

## Версионирование

Проект использует формат `MAJOR.MINOR.PATCH`.

- `MAJOR` меняется при несовместимых изменениях структуры сайта или формата контента.
- `MINOR` меняется при добавлении возможностей без поломки существующих статей.
- `PATCH` меняется при исправлениях ошибок, правках стилей и небольших улучшениях.

Текущая версия задаётся в `main.py` в переменной `SITE_VERSION` и отображается в футере сайта. История изменений ведётся в `CHANGELOG.md`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/check_content.py
```

Проверяющая утилита сообщает о проблемах в локальных статьях отдельно от тестов движка и не исправляет материалы автоматически.

## GitHub

Перед публикацией в GitHub статьи и медиа исключены через `.gitignore`:

```gitignore
articles/
```

Это значит, что GitHub-репозиторий содержит движок сайта, стили, скрипты и документацию, но не содержит учебные материалы.

Публикация:

```powershell
git remote add origin https://github.com/<логин>/knowbase-md.git
git push -u origin master
```
