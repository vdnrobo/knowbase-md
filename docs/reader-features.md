# Чтение, Учебные Блоки И Замечания

## Для Читателя

На странице статьи есть кнопка закладки; список доступен через иконку в шапке и ссылку «Закладки» в футере. Сохраняются до 500 ссылок. Удалённые статьи остаются в списке с пометкой «Статья недоступна» и могут быть удалены из закладок.

Место чтения сохраняется после прокрутки. На главной появляется «Продолжить чтение», а в ранее прочитанной статье — соответствующая кнопка. Переход по ней восстанавливает заголовок или позицию. Обычное открытие статьи, ссылки оглавления и возврат браузером не вызывают принудительной прокрутки. Хранятся последние 100 позиций.

Данные находятся только в `localStorage` текущего браузера: `knowbase.bookmarks.v1` и `knowbase.reading.v1`. Регистрации и синхронизации нет. Если хранилище недоступно, интерфейс остаётся рабочим, но изменения живут только до ухода со страницы.

Изображения статьи открываются по нажатию или с клавиатуры. В окне доступны масштаб 100–400% относительно вписанного изображения, перемещение, соседние изображения, сброс масштаба и закрытие Escape. Работают колесо мыши, перетаскивание и сенсорное масштабирование. Изображения-ссылки не перехватываются.

Кнопка над блоком кода копирует только текст кода. Если автоматическое копирование невозможно, открывается выделенный текст для ручного копирования. Без JavaScript текст и изображения остаются обычным содержимым статьи.

У заголовков второго–шестого уровней доступен значок копирования ссылки на раздел. Ссылка ведёт прямо к заголовку, в том числе внутри вкладки. Вкладки переключаются мышью и клавиатурой; без JavaScript их содержимое показывается последовательно.

Учебные маршруты доступны на `/paths` и в отдельном блоке главной. При открытии шага появляется дополнительная навигация маршрута над текстом статьи. Нижняя панель продолжает переключать статьи по категории. Возврат к маршруту доступен по его названию; защищённые шаги требуют обычный пароль раздела.

## Информационные Блоки, Вкладки И Маршруты

Синтаксис, готовые примеры и порядок администрирования собраны в [основной инструкции администратора](site-guide.md), разделы 14–18. Для информационных блоков используется `!!! note`, `!!! warning`, `!!! example`, `!!! tip`, для вкладок — `=== "Название"`, с отступом содержимого четыре пробела. Для новой независимой группы допустимо `===! "Название"`.

Маршруты редактируются в `learning-paths/<slug>.md`, с названием в первом заголовке `#` и списком статей в разделе `## Шаги`. Каталог локальный, не входит в Git и переносится на сервер отдельно. Для обновления кода установите актуальные зависимости из `requirements.txt`; новый Python-пакет — PyMdown Extensions.

## Вложения И Кнопки Скачивания

Разместите файл в папке `files/` нужной категории:

```text
articles/10-example/
  01-topic.md
  files/
    example.zip
    model.step
```

В Markdown:

```md
[Скачать архив](files/example.zip){.download}

[Скачать модель STEP](files/model.step){.download}
```

Это обычная Markdown-ссылка с классом `.download`. На сайте она отображается кнопкой с иконкой. При работе без JavaScript остаётся полноценной ссылкой для загрузки.

URL файла: `/10-example/files/example.zip`. Допускаются вложенные каталоги и Unicode-имена. Сервер выдаёт файл с заголовком скачивания, а не как исполняемую HTML-страницу. Нельзя выйти за пределы `files/`, включая переход через символические ссылки.

**Все файлы в `files/` публичны**, даже если статья защищена паролем. Не помещайте туда секретные материалы. Изображения для обычного отображения продолжайте хранить в `media/`.

## Связанные Статьи

Добавьте ведущие HTML-комментарии рядом с авторами и маркером защиты:

```md
<!-- authors: vdn -->
<!-- requires: /10-example/00-intro -->
<!-- related: /10-example/02-uart#connections, /20-other/01-basics -->
<!-- next: /10-example/03-practice -->
# Название статьи
```

`requires` выводится как «Перед чтением» в начале статьи, перед основным текстом. `related` («По теме») и `next` («Дальше») показываются после текста. Адреса перечисляются через запятую. Используйте внутренние URL сайта, при необходимости с якорем. Название берётся из целевой статьи. Повторы и отсутствующие статьи не выводятся; проверяющая утилита сообщает о неверных ссылках. Существующая нижняя навигация по файлам не меняется.

Закрытые статьи отображаются только названием с пометкой «закрыто»; переход по-прежнему требует пароль.

## Глоссарий

Создайте локальный файл `articles/glossary.json`:

```json
{
  "uart": {
    "title": "UART",
    "definition": "Интерфейс последовательного обмена данными между устройствами.",
    "url": "/10-example/02-uart"
  },
  "retract": {
    "title": "Ретракт",
    "definition": "Кратковременное втягивание филамента перед перемещением сопла."
  }
}
```

`title` и `definition` обязательны; `url` необязателен. Определения являются обычным текстом, не HTML. Ссылки допускают HTTP(S), внутренний путь или якорь.

В статье:

```md
Обмен выполняется через [[uart]].

Для [[uart|последовательного интерфейса]] нужны две сигнальные линии.
```

Термин открывает определение с клавиатуры или по нажатию. В коде, формулах и обычных ссылках разметка терминов не обрабатывается. Неизвестный идентификатор остаётся обычным текстом; утилита проверки сообщает об ошибке.

## Самопроверка

Самый удобный способ подготовить блок — открыть локальный [генератор](../tools/quiz-builder.html). Он не требует сервера и интернета: использует соседние файлы из `static/`. Перемещайте инструмент вместе с проектом, а не как единственный HTML-файл.

В генераторе доступны выбор типа задания, варианты, правильный ответ, подсказка, объяснение, предпросмотр, импорт существующего блока, копирование и скачивание `.md`. Инструмент ничего не публикует и не изменяет статьи.

Тест с одним правильным ответом:

````md
```quiz
{
  "type": "choice",
  "question": "Какие линии используются для обмена по UART?",
  "options": ["TX и RX", "SDA и SCL"],
  "correct": 0,
  "hint": "Передатчик одного устройства подключается к приёмнику другого.",
  "answer": "TX — передача, RX — приём. Также необходим общий GND."
}
```
````

`correct` — индекс с нуля: первый вариант имеет индекс `0`. Требуется от 2 до 10 непустых вариантов. Генератор выставляет индекс автоматически.

Открытое задание:

````md
```quiz
{
  "type": "exercise",
  "question": "Объясните, зачем двум платам общий GND.",
  "hint": "Подумайте, относительно чего измеряется напряжение.",
  "answer": "Общий GND задаёт общую точку отсчёта для уровней сигналов."
}
```
````

`question` обязателен, `hint` и `answer` необязательны. Вопрос, подсказка и объяснение поддерживают Markdown: **жирное выделение**, *курсив*, строчный `код`, списки, цитаты, ссылки, таблицы и блоки кода с указанием языка. Варианты ответа содержат обычный текст. Каждое задание оформлено отдельным блоком с фоном и рамкой; подсказка и ответ раскрываются внутри него.

Пример подсказки и ответа с форматированием:

````json
{
  "type": "exercise",
  "question": "Как вывести **значение переменной** в `Serial`?",
  "hint": "Используйте **Serial** и метод `println()`.\n\n- Проверьте скорость порта.\n- Сначала объявите переменную.",
  "answer": "Пример для одной переменной:\n\n```cpp\nint value = 42;\nSerial.println(value);\n```\n\nМетод `println()` добавляет перевод строки."
}
````

В JSON переносы строк внутри строк записываются как `\n`; в полях генератора вводите их обычной клавишей Enter. Форматирование работает и в офлайн-предпросмотре, и на странице без JavaScript. HTML не выполняется; опасные ссылки блокируются. Для браузерного предпросмотра локально поставляются [Marked](https://marked.js.org/) и [DOMPurify](https://github.com/cure53/DOMPurify) с лицензиями в `static/vendor/`, интернет для работы не нужен.

Максимум 16000 символов на вопрос, подсказку и объяснение, 4000 на вариант. Ответы проверяются в браузере и не сохраняются на сервере. Это самопроверка: правильные ответы доступны в HTML, поэтому блоки не предназначены для защищённых экзаменов.

Неверный JSON или структура не ломают страницу: вместо блока выводится сообщение, а проверяющая утилита показывает проблему. Примеры блоков, находящиеся внутри другого ограждённого блока кода, не превращаются в задания.

## Обновления

Укажите в начале статьи:

```md
<!-- updated: 2026-11-23 -->
<!-- update-note: Добавлена схема подключения и уточнены настройки порта. -->
# Название статьи
```

Дата должна быть действительной и иметь формат `YYYY-MM-DD`. Она показывается в статье; открытые материалы попадают на `/updates` и в список пяти последних обновлений на главной. Дата загрузки файлов не используется. Список новых статей продолжает работать отдельно.

Закрытые статьи и их описания обновлений не публикуются в общей ленте. Статьи без даты не получают вымышленной даты и в ленту обновлений не включаются.

## Замечания И Администратор

Задайте в `.env` длинный уникальный пароль:

```env
ADMIN_PASSWORD=your-long-unique-password
```

После перезапуска на страницах статей появится «Сообщить об ошибке». При выделении текста появляется кнопка с флажком; она подставляет цитату и ссылку на ближайший заголовок.

Форма требует **фамилию, имя, Telegram и текст замечания**. Контакт принимается как `@username` или `https://t.me/username`; существование аккаунта не проверяется. Имя и фамилия ограничены 100 символами каждое, контакт — 200, сообщение — 4000, цитата — 1000. Пробелы не считаются заполненным полем.

Обращения сохраняются в `feedback.sqlite3` рядом с базой активности внутри `DATA_DIR`. Файл не публикуется в Git. Персональные данные и цитаты видны только администратору. Telegram-бот и автоматическая рассылка не используются.

Закрытая страница просмотра: `/admin/feedback`. Пароль не связан с паролями статей. Список разделён на новые и обработанные обращения, доступны закрытие, повторное открытие, удаление и выход. На одной странице показывается до 50 записей.

Формы защищены CSRF-токенами, ловушкой спама и ограничением трёх сообщений за десять минут на анонимную браузерную сессию. Это базовая защита, а не полноценный антиспам-сервис. После пяти неверных попыток входа администратора сессия должна подождать десять минут. Cookie администратора действует до закрытия браузера, имеет `HttpOnly` и `SameSite=Strict`; за HTTPS-прокси добавляется `Secure`. Прокси должен корректно передавать `X-Forwarded-Proto`.

Без `ADMIN_PASSWORD` форма и приём замечаний отключены. При ошибке отправки заполненный текст остаётся в форме. Отправка замечания к закрытой статье требует действующего доступа к разделу. Периодически удаляйте обработанные обращения, которые больше не нужны; резервные копии базы также содержат персональные данные.

## Проверка Перед Публикацией

```powershell
.\.venv\Scripts\python.exe tools/check_content.py
```

Для другого каталога:

```powershell
.\.venv\Scripts\python.exe tools/check_content.py --articles C:\path\to\articles
```

Проверяются внутренние ссылки и заголовки, изображения, вложения, термины, задания, даты, связи, профили авторов и маршруты. Проверка маршрутов выявляет неверную структуру, неизвестные статьи и якоря, повторные шаги; можно передать `--paths C:\path\to\learning-paths`. Отсутствующие авторы и повторяющиеся заголовки — предупреждения. Ошибки дают код завершения `1`, при отсутствии ошибок — `0`. Внешние сайты не запрашиваются. Файлы и база статистики не меняются; исправления нужно вносить вручную.

При обновлении сервера обновляйте все файлы кода и `static/`, а не только `main.py`. Сохраняйте локальные `articles/`, `authors/`, `learning-paths/`, `announcement.md`, `.env` и `data/`. Устанавливайте зависимости и перезапускайте существующий сервис; подробная последовательность приведена в [инструкции администратора](site-guide.md). Для первого запуска подготовлена [инструкция установки на Ubuntu 26.04](deploy-ubuntu-26.04.md).
