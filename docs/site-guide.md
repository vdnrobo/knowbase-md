# Инструкция по работе с сайтом

Этот документ описывает, как обслуживать сайт `knowbase-md`: добавлять разделы, писать статьи, подключать изображения, защищать материалы паролем и менять базовые настройки.

## 1. Как сайт собирает материалы

При каждом открытии страницы сервер читает папку `articles/` и строит список разделов заново. Контент хранится в файлах; локальная база SQLite используется только для статистики посещений и дат появления статей.

Разделом считается любая папка внутри `articles/`:

```text
articles/
  10-3D/
  15-lections/
  90-YE-2026/
```

Папки сортируются по имени. Поэтому удобно начинать названия с чисел: `10-3D`, `20-manipulator`, `90-archive`.

Внутри раздела сайт ищет:

- `category.txt` - название раздела на главной и на отдельной странице категории;
- `description.txt` - описание раздела;
- `sections.txt` - необязательное разделение статей на подгруппы внутри раздела;
- `*.md` - статьи;
- `media/` - изображения и другие медиафайлы для статей.

Профили авторов хранятся отдельно в `authors/`. Этот каталог, как и `articles/`, считается локальным контентом и не публикуется в GitHub.

## 2. Как добавить раздел

Создайте новую папку внутри `articles/`:

```text
articles/
  30-new-course/
    category.txt
    description.txt
    00-intro.md
```

Пример `category.txt`:

```text
Новый курс
```

Пример `description.txt`:

```md
Короткое описание раздела. Здесь можно использовать [ссылки](https://example.com).
```

Описание раздела рендерится как Markdown, поэтому в нём работают ссылки, выделение и простой текстовый формат.

Если внутри раздела много статей, можно добавить `sections.txt`, чтобы на главной и на странице категории статьи были сгруппированы по подгруппам:

```text
00-09: Основы
10-19: Работа с моделью
20-29: Дополнительно
```

Диапазоны включительные. Номер статьи берётся из первых двух цифр имени файла: `05-cv-markers-and-codes.md` попадает в диапазон `00-09`, а `11-model-work.md` - в диапазон `10-19`. Пустые строки игнорируются, строки-комментарии можно начинать с `#`. Если статья не попала ни в один диапазон, она будет показана в группе `Без раздела`.

### Отдельная страница категории

Каждый непустой раздел получает страницу `/categories/<имя-папки>`, например `/categories/04-ETZ`. На ней выводятся название, Markdown-описание, имена и фотографии авторов, поиск по разделу и статьи. Порядок статей и подгруппы совпадают с главной страницей.

С главной можно перейти по ссылке «Открыть раздел». Ссылки на категорию также доступны над текстом статьи, в форме ввода пароля, в заголовках групп на странице автора и в списке разделов на странице 404.

Поиск внутри категории учитывает названия, текст статей, имена авторов и подгруппы. Пустые подгруппы скрываются, а найденные защищённые статьи автоматически раскрывают свой список. Страница категории публична, но открытие защищённой статьи по-прежнему требует пароль. Пустая или неизвестная категория возвращает 404.

## 3. Как добавить статью

Создайте `.md`-файл внутри нужного раздела:

```text
articles/30-new-course/01-first-topic.md
```

Первый заголовок первого уровня становится названием статьи:

```md
# Первая тема

Текст статьи.
```

Если заголовка `# ...` нет, сайт использует имя файла без расширения.

Статьи сортируются по имени файла. Для учебного курса удобно использовать номера:

```text
00-intro.md
01-history.md
02-practice.md
```

Авторов и редакторов статьи можно указать служебными HTML-комментариями в начале файла:

```md
<!-- authors: vdn, ivan-petrov -->
<!-- editors: dps -->

# Первая тема
```

Если статья защищена паролем, все служебные комментарии ставятся в начале файла:

```md
<!-- protected -->
<!-- authors: vdn -->
<!-- editors: dps, ivan-petrov -->

# Закрытая статья
```

Эти комментарии не отображаются на странице и удаляются до рендера Markdown. Если авторов или редакторов несколько, их slug перечисляются через запятую. Повторное указание человека в одной роли не дублирует его; порядок имён сохраняется. Пустой список допустим. Также поддерживаются формы `author:` и `editor:` для одного человека.

Редакторы берутся из того же каталога `authors/`, что и авторы: например, `dps` соответствует папке `authors/dps/`. Авторы и редакторы указываются над текстом статьи: сначала блок авторов, чуть ниже отдельный блок редакторов. Оба блока показывают имя, фотографию и ссылку на страницу профиля. У статьи могут быть только редакторы, только авторы или обе роли; при отсутствии редакторов их блок не появляется.

На странице профиля отдельно отображаются «Статьи автора» и «Статьи под редакцией». Внутри каждого списка сохраняется группировка по категориям. Один человек может иметь обе роли в одной статье: тогда статья появится в обоих списках. Защищённые статьи помечаются как закрытые, доступ к их тексту по-прежнему проверяется при открытии.

Поиск на главной и страницах категорий учитывает имена редакторов наряду с именами авторов. Для защищённых статей в публичный поисковый индекс входят только заголовок и имена авторов и редакторов, без текста статьи. В заголовках категорий редакторы не добавляются к списку авторов.

## 4. Как добавить автора

Создайте папку автора внутри `authors/`:

```text
authors/
  vdn/
    profile.md
    photo.jpg
```

В `profile.md` первый заголовок первого уровня считается именем автора, а остальной текст - кратким описанием:

```md
# Виктор Николаев

Преподаватель, инженер и автор учебных материалов по цифровому производству.
```

Фото автора должно называться `photo` и иметь одно из расширений: `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`, `.svg`.

После добавления профиля появятся:

- `/authors` - список авторов;
- `/authors/vdn` - страница автора;
- `/authors/vdn/photo.jpg` - фото автора, если файл существует.

Если в статье указан автор или редактор, для которого ещё нет папки в `authors/`, сайт не ломается: вместо имени будет показан его slug, а вместо фотографии - инициалы. Страница профиля будет содержать связанные статьи с разделением по ролям. Профили людей, указанных только редакторами, также доступны из блока авторов на главной и общего списка `/authors`.

## 5. Markdown-возможности

В статьях поддерживаются стандартные элементы Markdown:

- заголовки;
- абзацы;
- нумерованные и маркированные списки;
- таблицы;
- ссылки;
- изображения;
- блоки кода;
- встроенный HTML, если он нужен точечно.

Содержание статьи строится автоматически по заголовкам. В боковом оглавлении вложенные пункты можно сворачивать.

## 6. Изображения и подписи

Рекомендуемая структура:

```text
articles/30-new-course/
  01-first-topic.md
  media/
    printer.jpg
```

Вставка изображения:

```md
![Подпись под изображением](media/printer.jpg)
```

Если картинка стоит отдельным абзацем, сайт превратит её в `figure` и покажет подпись под изображением.

Если подпись не нужна:

```md
![](media/printer.jpg)
```

Inline-картинки внутри строки с другим текстом не превращаются в `figure`, чтобы не ломать верстку абзацев.

## 7. Формулы LaTeX

Для формул используется MathJax.

Строчная формула:

```md
Сопротивление считается как $R = \frac{U}{I}$.
```

Отдельная формула:

```md
$$
R = \frac{U}{I}
$$
```

Также поддерживаются формы `\( ... \)` и `\[ ... \]`.

## 8. Защищённые статьи

Чтобы закрыть статью паролем, добавьте в самое начало Markdown-файла маркер:

```md
<!-- protected -->

# Закрытая статья
```

Маркер не отображается на странице.

Пароль задаётся один на весь раздел через переменную окружения. Например, для папки:

```text
articles/10-3D/
```

переменная будет:

```env
ARTICLE_PASSWORD_10_3D=your-password
```

Правило формирования имени:

1. берётся имя папки раздела;
2. переводится в верхний регистр;
3. все символы кроме букв и цифр заменяются на `_`;
4. добавляется префикс `ARTICLE_PASSWORD_`.

Примеры:

| Папка раздела | Переменная |
| --- | --- |
| `10-3D` | `ARTICLE_PASSWORD_10_3D` |
| `05-knowledge-base` | `ARTICLE_PASSWORD_05_KNOWLEDGE_BASE` |
| `90-YE-2026` | `ARTICLE_PASSWORD_90_YE_2026` |

После правильного ввода пароля доступ открывается ко всем защищённым статьям этого раздела до закрытия браузера.

## 9. Главная страница и поиск

Главная страница собирается автоматически из всех разделов.

Обычные статьи видны сразу. Защищённые статьи скрыты под кнопкой `Показать защищённые статьи` и помечены как закрытые.

Внизу главной страницы отображается блок авторов. В нём показаны маленькое фото и имя автора; клик по карточке открывает страницу автора со списком его материалов.

Поиск работает по:

- названию раздела;
- описанию раздела;
- названию статьи;
- имени автора;
- тексту статьи.

Если поисковый запрос совпал с защищённой статьёй, скрытый список защищённых статей раскрывается автоматически.

## 10. Объявление на главной

Файл `announcement.md` отображается на главной странице отдельным блоком. Его можно использовать для коротких объявлений, ссылок и предупреждений.

Это локальный файл конкретной установки сайта. Он добавлен в `.gitignore`, поэтому не публикуется в GitHub вместе с кодом и не затирается при обычном обновлении репозитория.

Механизм работы:

1. при открытии главной страницы сайт ищет `announcement.md` рядом с `main.py`;
2. если файл есть и не пустой, его содержимое рендерится как Markdown;
3. готовый HTML выводится над списком разделов;
4. если файла нет или он пустой, блок объявления не показывается.

Минимальный пример:

```md
## Внимание

В субботу сайт может быть недоступен из-за обновления материалов.
```

Если объявление не нужно, очистите файл или удалите его.

## 11. Футер, версия, переходы, иконка и оформление

Текущая версия сайта задаётся в `main.py` в переменной `SITE_VERSION`. Она автоматически выводится в футере в формате `v1.7.0`.

Текст футера задаётся в `main.py` в переменной `FOOTER_TEXT`, а ссылка на репозиторий - в `GITHUB_URL`. При обычном изменении номера версии нужно менять только `SITE_VERSION`.

Иконки:

- `favicon.ico` - иконка вкладки браузера;
- `static/site-icon.svg` - внутренняя SVG-иконка в интерфейсе сайта.

Основной внешний вид находится в `static/style.css`. Поведение поиска, оглавления и раскрытия защищённых статей находится в `static/site.js`.

Основные скругления интерфейса задаются CSS-переменными `--radius-sm`, `--radius` и `--radius-lg` в начале `static/style.css`.

### Боковой блок главной страницы

При ширине окна от 1200 px справа от основного содержимого показываются посетители за последние 24 часа и пять новых открытых статей. На более узких экранах блок скрыт.

Счётчик учитывает браузеры по анонимному cookie `site_visitor`: повторные посещения страниц с тем же cookie обновляют время последнего визита, но не увеличивают число посетителей. Визиты на главную, страницы категорий, страницы статей, форму доступа к статье и страницы авторов учитываются; запросы к медиа, статике, 404 и POST-формам не учитываются. Распространённые боты исключаются по User-Agent. Это приблизительная оценка: другой браузер или очистка cookie создают нового посетителя, а посетители с отключёнными cookie могут учитываться повторно.

Cookie действует год, имеет `HttpOnly`, `SameSite=Lax` и флаг `Secure` при `X-Forwarded-Proto: https`. В базе хранятся только хеш идентификатора и время последнего визита; IP-адреса и User-Agent не сохраняются. Записи о посетителях без визитов за последние 24 часа удаляются при следующем учитываемом визите.

Даты появления статей сохраняются отдельно. При первом открытии главной существующие статьи сортируются по времени изменения Markdown-файлов. Затем впервые найденные открытые статьи получают время обнаружения. Последующее редактирование файла сохраняет дату в списке новых статей. Защищённые статьи в боковом списке не показываются.

Данные хранятся в `data/activity.sqlite3`; каталог автоматически создаётся и исключён из Git. Его путь можно изменить через `DATA_DIR` в `.env`. Пользователь, запускающий сайт, должен иметь право записи в этот каталог. При обновлении сайта сохраняйте `data/`, чтобы не потерять статистику и даты появления статей. Если база недоступна, сайт продолжает работать, а счётчик показывает прочерк.

## 12. Локальный запуск

```powershell
.\.venv\Scripts\python.exe main.py
```

Если виртуальное окружение ещё не создано:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Для разработки лучше использовать порт `8000`:

```env
HOST=127.0.0.1
PORT=8000
```

## 13. Обновление сайта на сервере

Минимальная схема обновления:

1. остановить сервис сайта на сервере;
2. заменить `main.py`, `static/` и `requirements.txt`;
3. отдельно загрузить нужные разделы из `articles/`, если нужно обновить контент;
4. проверить `.env`;
5. установить зависимости;
6. запустить сервис снова.

Репозиторий GitHub хранит код и документацию. Контент `articles/`, профили `authors/` и локальное объявление `announcement.md` переносятся на сервер отдельно.
