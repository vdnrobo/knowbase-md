# Инструкция по работе с сайтом

Это основная инструкция администратора `knowbase-md`: как добавлять разделы и статьи, оформлять учебные материалы, создавать маршруты, настраивать доступ и обновлять работающий сайт. Отдельный [справочник возможностей](reader-features.md) описывает задания, глоссарий, вложения и приём замечаний.

## 1. Как сайт собирает материалы

При каждом открытии страницы сервер читает папку `articles/` и строит список разделов заново. Контент хранится в файлах; SQLite используется для статистики посещений, дат появления статей и отдельно для замечаний читателей.

Разделом считается любая папка внутри `articles/`:

```text
articles/
  10-3D/
  15-lections/
  90-YE-2026/
```

Папки сортируются по имени. Поэтому удобно начинать названия с чисел: `10-3D`, `20-manipulator`, `90-archive`.

Внутри раздела сайт ищет:

- `category.txt` - название раздела на главной и на отдельной странице категории;
- `description.txt` - описание раздела;
- `sections.txt` - необязательное разделение статей на подгруппы внутри раздела;
- `*.md` - статьи;
- `media/` - изображения и другие медиафайлы для статей.

Профили авторов хранятся отдельно в `authors/`. Этот каталог, как и `articles/`, считается локальным контентом и не публикуется в GitHub.

## 2. Как добавить раздел

Создайте новую папку внутри `articles/`:

```text
articles/
  30-new-course/
    category.txt
    description.txt
    00-intro.md
```

Пример `category.txt`:

```text
Новый курс
```

Пример `description.txt`:

```md
Короткое описание раздела. Здесь можно использовать [ссылки](https://example.com).
```

Описание раздела рендерится как Markdown, поэтому в нём работают ссылки, выделение и простой текстовый формат.

Если внутри раздела много статей, можно добавить `sections.txt`, чтобы на главной и на странице категории статьи были сгруппированы по подгруппам:

```text
00-09: Основы
10-19: Работа с моделью
20-29: Дополнительно
```

Диапазоны включительные. Номер статьи берётся из первых двух цифр имени файла: `05-cv-markers-and-codes.md` попадает в диапазон `00-09`, а `11-model-work.md` - в диапазон `10-19`. Пустые строки игнорируются, строки-комментарии можно начинать с `#`. Если статья не попала ни в один диапазон, она будет показана в группе `Без раздела`.

### Отдельная страница категории

Каждый непустой раздел получает страницу `/categories/<имя-папки>`, например `/categories/04-ETZ`. На ней выводятся название, Markdown-описание, имена и фотографии авторов, поиск по разделу и статьи. Порядок статей и подгруппы совпадают с главной страницей.

С главной можно перейти по ссылке «Открыть раздел». Ссылки на категорию также доступны над текстом статьи, в форме ввода пароля, в заголовках групп на странице автора и в списке разделов на странице 404.

Поиск внутри категории учитывает названия, текст статей, имена авторов и подгруппы. Пустые подгруппы скрываются, а найденные защищённые статьи автоматически раскрывают свой список. Страница категории публична, но открытие защищённой статьи по-прежнему требует пароль. Пустая или неизвестная категория возвращает 404.

## 3. Как добавить статью

Создайте `.md`-файл внутри нужного раздела:

```text
articles/30-new-course/01-first-topic.md
```

Первый заголовок первого уровня становится названием статьи:

```md
# Первая тема

Текст статьи.
```

Если заголовка `# ...` нет, сайт использует имя файла без расширения.

Статьи сортируются по имени файла. Для учебного курса удобно использовать номера:

```text
00-intro.md
01-history.md
02-practice.md
```

Авторов и редакторов статьи можно указать служебными HTML-комментариями в начале файла:

```md
<!-- authors: vdn, ivan-petrov -->
<!-- editors: dps -->

# Первая тема
```

Если статья защищена паролем, все служебные комментарии ставятся в начале файла:

```md
<!-- protected -->
<!-- authors: vdn -->
<!-- editors: dps, ivan-petrov -->

# Закрытая статья
```

Эти комментарии не отображаются на странице и удаляются до рендера Markdown. Если авторов или редакторов несколько, их slug перечисляются через запятую. Повторное указание человека в одной роли не дублирует его; порядок имён сохраняется. Пустой список допустим. Также поддерживаются формы `author:` и `editor:` для одного человека.

Редакторы берутся из того же каталога `authors/`, что и авторы: например, `dps` соответствует папке `authors/dps/`. Авторы и редакторы указываются над текстом статьи: сначала блок авторов, чуть ниже отдельный блок редакторов. Оба блока показывают имя, фотографию и ссылку на страницу профиля. У статьи могут быть только редакторы, только авторы или обе роли; при отсутствии редакторов их блок не появляется.

На странице профиля отдельно отображаются «Статьи автора» и «Статьи под редакцией». Внутри каждого списка сохраняется группировка по категориям. Один человек может иметь обе роли в одной статье: тогда статья появится в обоих списках. Защищённые статьи помечаются как закрытые, доступ к их тексту по-прежнему проверяется при открытии.

Поиск на главной и страницах категорий учитывает имена редакторов наряду с именами авторов. Для защищённых статей в публичный поисковый индекс входят только заголовок и имена авторов и редакторов, без текста статьи. В заголовках категорий редакторы не добавляются к списку авторов.

## 4. Как добавить автора

Создайте папку автора внутри `authors/`:

```text
authors/
  vdn/
    profile.md
    photo.jpg
```

В `profile.md` первый заголовок первого уровня считается именем автора, а остальной текст - кратким описанием:

```md
# Виктор Николаев

Преподаватель, инженер и автор учебных материалов по цифровому производству.
```

Фото автора должно называться `photo` и иметь одно из расширений: `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`, `.svg`.

На главной авторы показываются в карусели: один слайд содержит фотографию, полное имя и описание из `profile.md` с поддержкой Markdown. Имя ведёт на страницу профиля. Пишите описание кратко: оно целиком отображается и на главной. При отсутствии фото используются инициалы, при отсутствии описания - стандартная подпись.

Стрелки переключают авторов по кругу; когда фокус находится в карусели, работают также клавиши влево и вправо. Автоматического переключения нет. Для одного автора стрелки не показываются. Без JavaScript все авторы остаются видны обычным списком.

После добавления профиля появятся:

- `/authors` - список авторов;
- `/authors/vdn` - страница автора;
- `/authors/vdn/photo.jpg` - фото автора, если файл существует.

Если в статье указан автор или редактор, для которого ещё нет папки в `authors/`, сайт не ломается: вместо имени будет показан его slug, а вместо фотографии - инициалы. Страница профиля будет содержать связанные статьи с разделением по ролям. Профили людей, указанных только редакторами, также доступны из блока авторов на главной и общего списка `/authors`.

## 5. Markdown-возможности

Закладки, продолжение чтения, увеличение изображений и копирование кода работают автоматически. Новые авторские форматы (вложения, глоссарий, связи, обновления и самопроверка), локальный генератор и настройка замечаний описаны в [reader-features.md](reader-features.md).

В статьях поддерживаются стандартные элементы Markdown:

- заголовки;
- абзацы;
- нумерованные и маркированные списки;
- таблицы;
- ссылки;
- изображения;
- блоки кода;
- информационные блоки и вкладки (разделы 14–15 этой инструкции);
- встроенный HTML, если он нужен точечно.

Содержание статьи строится автоматически по заголовкам. В боковом оглавлении вложенные пункты можно сворачивать.

## 6. Изображения и подписи

Рекомендуемая структура:

```text
articles/30-new-course/
  01-first-topic.md
  media/
    printer.jpg
```

Вставка изображения:

```md
![Подпись под изображением](media/printer.jpg)
```

Если картинка стоит отдельным абзацем, сайт превратит её в `figure` и покажет подпись под изображением.

Если подпись не нужна:

```md
![](media/printer.jpg)
```

Inline-картинки внутри строки с другим текстом не превращаются в `figure`, чтобы не ломать верстку абзацев.

## 7. Формулы LaTeX

Для формул используется MathJax.

Строчная формула:

```md
Сопротивление считается как $R = \frac{U}{I}$.
```

Отдельная формула:

```md
$$
R = \frac{U}{I}
$$
```

Также поддерживаются формы `\( ... \)` и `\[ ... \]`.

## 8. Защищённые статьи

Чтобы закрыть статью паролем, добавьте в самое начало Markdown-файла маркер:

```md
<!-- protected -->

# Закрытая статья
```

Маркер не отображается на странице.

Пароль задаётся один на весь раздел через переменную окружения. Например, для папки:

```text
articles/10-3D/
```

переменная будет:

```env
ARTICLE_PASSWORD_10_3D=your-password
```

Правило формирования имени:

1. берётся имя папки раздела;
2. переводится в верхний регистр;
3. все символы кроме букв и цифр заменяются на `_`;
4. добавляется префикс `ARTICLE_PASSWORD_`.

Примеры:

| Папка раздела | Переменная |
| --- | --- |
| `10-3D` | `ARTICLE_PASSWORD_10_3D` |
| `05-knowledge-base` | `ARTICLE_PASSWORD_05_KNOWLEDGE_BASE` |
| `90-YE-2026` | `ARTICLE_PASSWORD_90_YE_2026` |

После правильного ввода пароля доступ открывается ко всем защищённым статьям этого раздела до закрытия браузера.

## 9. Главная страница и поиск

Главная страница собирается автоматически из всех разделов.

Обычные статьи видны сразу. Защищённые статьи скрыты под кнопкой `Показать защищённые статьи` и помечены как закрытые.

Внизу главной страницы отображается блок авторов. В нём показаны маленькое фото и имя автора; клик по карточке открывает страницу автора со списком его материалов.

Поиск работает по:

- названию раздела;
- описанию раздела;
- названию статьи;
- имени автора;
- тексту статьи.

Если поисковый запрос совпал с защищённой статьёй, скрытый список защищённых статей раскрывается автоматически.

## 10. Объявление на главной

Файл `announcement.md` отображается на главной странице отдельным блоком. Его можно использовать для коротких объявлений, ссылок и предупреждений.

Это локальный файл конкретной установки сайта. Он добавлен в `.gitignore`, поэтому не публикуется в GitHub вместе с кодом и не затирается при обычном обновлении репозитория.

Механизм работы:

1. при открытии главной страницы сайт ищет `announcement.md` рядом с `main.py`;
2. если файл есть и не пустой, его содержимое рендерится как Markdown;
3. готовый HTML выводится над списком разделов;
4. если файла нет или он пустой, блок объявления не показывается.

Минимальный пример:

```md
## Внимание

В субботу сайт может быть недоступен из-за обновления материалов.
```

Если объявление не нужно, очистите файл или удалите его.

## 11. Футер, версия, переходы, иконка и оформление

В шапке каждой страницы доступно меню «Тема»: классическая, зимняя, весенняя, летняя, осенняя, «67», волшебная, Hello Kitty, «548», Robo548 и «Миньоны». По умолчанию используется классическая тема. Выбор сохраняется в `localStorage` браузера под ключом `siteTheme` и применяется до загрузки стилей, в том числе на страницах пароля и 404. На другом устройстве тема выбирается независимо. При недоступном хранилище переключение работает до ухода с текущей страницы; без JavaScript остаётся классическое оформление.

Рядом с меню находится отдельный переключатель с солнцем и луной: светлый или тёмный режим. Он доступен для классической, зимней, весенней, летней, осенней, «67» и волшебной тем и не добавляет новые пункты в меню. Hello Kitty, «548», Robo548 и «Миньоны» всегда светлые: переключатель для них скрыт. Предпочтительный режим сохраняется отдельно, под ключом `siteColorMode` (`light` или `dark`), и восстанавливается при возврате к теме с поддержкой тёмного режима. По умолчанию используется светлый режим; настройка применяется до загрузки CSS, чтобы избежать вспышки светлого фона при переходах. Переключатель работает с клавиатуры, включая пробел. Если хранилище заблокировано, переключение продолжает работать на текущей странице.

Тёмные палитры находятся в `static/dark.css`. Они меняют поверхности, текст, ссылки, формы, задания и нижнюю навигацию, сохраняя цветовые акценты каждой темы. Фоновые паттерны адаптированы для тёмного фона; фотографии, фавикон и угловые иллюстрации не перекрашиваются.

Тема «Миньоны» использует светлую жёлтую палитру с синими ссылками и диагональные ряды мультяшных мишек Боба. В правом нижнем углу широкого экрана показан готовый рисунок миньона, предоставленный пользователем; внешний белый фон удалён локально без изменения рисунка и белых колец глаз. Директор в теме «548» и Arduino Nano в Robo548 перерисованы более плоско и мультяшно, с тонкими контурами; их прежние размеры и отступы сохранены.

Hello Kitty использует розовые тона, бабочек на фоне и персонажа в углу. В теме «548» оранжевые акценты, логотип школы на фоне и фигурка директора в стиле Funko Pop по предоставленной фотографии. Robo548 использует синие тона, векторную эмблему с шестерёнкой на фоне и рисунок Arduino Nano в углу. Эмблема перерисована по предоставленному образцу в `static/themes/robo548.svg`; сам `favicon.ico` не изменяется. Все ресурсы хранятся локально в `static/themes/`, внешние изображения при открытии сайта не загружаются. Угловые рисунки этих тем не перекрывают текст и показываются только на широких экранах.

Сезонные темы меняют цвета интерфейса и добавляют полупрозрачный фон: снежинки, цветы, круги-фламинго или листья. В теме «67» чередуются округлые мультяшные цифры и персонаж с леденцом на прозрачном фоне; волшебная тема использует бело-чёрно-красную палитру и контурный рисунок на метле. Во всех неклассических темах рисунки расположены диагональными рядами, без поворота самих изображений. Фоновые элементы компактные и полупрозрачные; плотность и масштаб адаптируются к ширине экрана. В теме «67» персонаж заметнее цифр: его отдельный слой имеет видимость 50%, цифры — 12%; движение слоёв синхронизировано. Персонаж сохраняет светлые цвета и в тёмном режиме.

На экранах шириной от 1360 px в правом нижнем углу появляется неподвижная непрозрачная иллюстрация: обычный снеговик из трёх шаров зимой, тонкие цветущие веточки весной, пляжный зонт летом, фонарь с дождём без листьев осенью, Тунг-Тунг-Сахур с естественными глазами в теме «67» и красная метла в волшебной теме. Рисунки минималистичные, с тонкими контурами. Снеговик, зонт и фонарь сдвинуты влево без изменения высоты, куст отражён горизонтально. Часть угловых рисунков слегка скрыта за краем экрана. Метла не обрезается: между ней и правым и нижним краями остаётся зазор 2 px; в статьях такой же зазор оставлен над панелью навигации. Размер ограничен свободным полем справа от контента; в статье низ иллюстрации немного скрывается под нижней навигацией. На узких экранах, при печати и в классической теме иллюстрации скрыты. Они не перехватывают нажатия. Изображения и запросы к генератору находятся в `static/themes/corners/`. Весенние фоновые цветы сделаны контрастнее, но остаются полупрозрачными. В зимней, летней и осенней темах по одному объекту на плитку: ячейка 256 px на компьютере и 216 px на мобильном экране. В волшебной теме рисунки и расстояния между ними крупнее: ячейка 320 px на компьютере и 280 px на мобильном экране.

Паттерны медленно движутся, но при системной настройке уменьшения движения остаются неподвижными. Основная поверхность для чтения непрозрачная: белая в светлом режиме, тёмная в тёмном; фотографии, фавикон и логотип не перекрашиваются. Подсветка кода сохраняет свои цвета, а в волшебной теме фон кода становится нейтрально-чёрным. Файлы фонов и запросы к встроенному генератору изображений хранятся в `static/themes/`.

Текущая версия сайта задаётся в `main.py` в переменной `SITE_VERSION`. Она автоматически выводится в футере в формате `v2.0.2`.

Текст футера задаётся в `main.py` в переменной `FOOTER_TEXT`, а ссылка на репозиторий - в `GITHUB_URL`. При обычном изменении номера версии нужно менять только `SITE_VERSION`.

Иконки:

- `favicon.ico` - иконка вкладки браузера;
- `static/site-icon.svg` - внутренняя SVG-иконка в интерфейсе сайта.

Основной внешний вид находится в `static/style.css`. Поведение поиска, оглавления и раскрытия защищённых статей находится в `static/site.js`.

Основные скругления интерфейса задаются CSS-переменными `--radius-sm`, `--radius` и `--radius-lg` в начале `static/style.css`.

### Боковой блок главной страницы

При ширине окна от 1200 px справа от основного содержимого показываются посетители за последние 24 часа и пять новых открытых статей. На более узких экранах блок скрыт.

Счётчик учитывает браузеры по анонимному cookie `site_visitor`: повторные посещения страниц с тем же cookie обновляют время последнего визита, но не увеличивают число посетителей. Визиты на главную, страницы категорий, страницы статей, форму доступа к статье и страницы авторов учитываются; запросы к медиа, статике, 404 и POST-формам не учитываются. Распространённые боты исключаются по User-Agent. Это приблизительная оценка: другой браузер или очистка cookie создают нового посетителя, а посетители с отключёнными cookie могут учитываться повторно.

Cookie действует год, имеет `HttpOnly`, `SameSite=Lax` и флаг `Secure` при `X-Forwarded-Proto: https`. В базе хранятся только хеш идентификатора и время последнего визита; IP-адреса и User-Agent не сохраняются. Записи о посетителях без визитов за последние 24 часа удаляются при следующем учитываемом визите.

Даты появления статей сохраняются отдельно. При первом открытии главной существующие статьи сортируются по времени изменения Markdown-файлов. Затем впервые найденные открытые статьи получают время обнаружения. Последующее редактирование файла сохраняет дату в списке новых статей. Защищённые статьи в боковом списке не показываются.

Данные хранятся в `data/activity.sqlite3`; каталог автоматически создаётся и исключён из Git. Его путь можно изменить через `DATA_DIR` в `.env`. Пользователь, запускающий сайт, должен иметь право записи в этот каталог. При обновлении сайта сохраняйте `data/`, чтобы не потерять статистику и даты появления статей. Если база недоступна, сайт продолжает работать, а счётчик показывает прочерк.

## 13. Обновление сайта на сервере

Для первой установки на пустой сервер используйте [инструкцию для Ubuntu 26.04](deploy-ubuntu-26.04.md). Этот раздел посвящён обновлению уже работающей установки.

Обновляйте уже работающий сервис; создавать второй процесс или новый конфиг Nginx для этих возможностей не требуется. Ниже используется имя `robo548-site`. Если ваш существующий сервис называется иначе, замените значение `SERVICE`.

После подключения по SSH перейдите в фактическую директорию проекта и проверьте сервис:

```bash
cd /path/to/site
SERVICE=robo548-site
sudo systemctl status "$SERVICE" --no-pager
git status --short
umask 022
git pull --ff-only origin master
.venv/bin/python -m pip install -r requirements.txt
```

Не используйте `git reset --hard` для разрешения конфликтов: сначала разберите локальные изменения. Если обновляете файлы без Git, переносите весь код и `static/`, включая новые модули, иконки и зависимости. Одной замены `main.py` недостаточно.

Рабочие `articles/`, `authors/`, `learning-paths/`, `announcement.md`, `.env` и `data/` не входят в репозиторий. Их нужно сохранять, а необходимые изменения переносить отдельно. Например, с локального PowerShell можно загрузить маршруты так:

```powershell
$server = "user@host"
$remote = "/path/to/site"
scp -r .\learning-paths "${server}:${remote}/"
```

Копирование объединяет содержимое каталогов. Если маршрут удалён локально, удалите соответствующий `.md` на сервере отдельно, иначе он продолжит отображаться. Убедитесь, что пользователь существующего сервиса может читать новые файлы.

На сервере выполните проверки из директории проекта:

```bash
.venv/bin/python -m py_compile main.py knowledge.py feedback.py learning_paths.py
.venv/bin/python -m unittest discover -s tests
.venv/bin/python tools/check_content.py
```

Проверяющая утилита выводит ошибки контента отдельно от тестов движка. Изучите сообщения, исправьте неверные ссылки и шаги маршрутов. После успешной проверки перезапустите существующий сервис:

```bash
sudo systemctl restart "$SERVICE"
sudo systemctl status "$SERVICE" --no-pager
sudo journalctl -u "$SERVICE" -n 50 --no-pager
```

Откройте главную, статью с вкладками, `/paths` и защищённый шаг маршрута. Если стили остались старыми, обновите страницу без кеша. Изменения Markdown-файлов подхватываются следующим запросом без перезапуска; изменения Python, зависимостей или `.env` требуют перезапуска процесса.

## 14. Информационные блоки

Используйте блоки для предупреждений и коротких пояснений. Они остаются развёрнутыми и читаются без JavaScript. Поддерживаются четыре типа:

| Тип | Заголовок по умолчанию | Применение |
| --- | --- | --- |
| `note` | Важно | Существенное условие или ограничение |
| `warning` | Осторожно | Риск повреждения или опасное подключение |
| `example` | Пример | Разобранный случай |
| `tip` | Совет | Практическая рекомендация |

После строки `!!! тип` содержимое пишется с отступом **четыре пробела**. Необязательный заголовок задаётся в двойных кавычках:

````md
!!! warning "Проверьте питание"
    **Отключите питание** перед изменением подключения.

    - Проверьте общий GND.
    - Уточните допустимые уровни напряжения.

!!! example
    Строчный код: `Serial.println(value)`.

    ```cpp
    int value = 42;
    Serial.println(value);
    ```
````

В блоках работают списки, таблицы, ссылки, изображения, код и формулы. Обычный текст статьи после блока пишется без отступа. Для нейтральной заметки достаточно `!!! note`. Цвета автоматически адаптируются к теме и светлому/тёмному режиму.

## 15. Вкладки внутри статьи

Вкладки подходят для альтернативных инструкций, например для двух сред разработки. Заголовок начинается с `===`, содержимое имеет отступ **четыре пробела**:

````md
=== "Arduino IDE"
    Установите пакет поддержки платы в менеджере плат.

    ```cpp
    Serial.begin(115200);
    ```

=== "PlatformIO"
    Укажите плату и фреймворк в `platformio.ini`.

    ```ini
    [env:pico]
    platform = raspberrypi
    board = pico
    framework = arduino
    ```
````

Соседние вкладки объединяются в одну группу. Чтобы начать независимую группу, вставьте между группами обычный абзац без отступа или используйте `===! "Название первой вкладки новой группы"`.

Первая вкладка открывается автоматически. Доступны клавиши влево/вправо, Home и End; длинный ряд вкладок прокручивается горизонтально. Содержимое поддерживает обычный Markdown, таблицы, изображения, формулы и блоки кода с подсветкой и копированием. Без JavaScript все панели показаны подряд с названиями.

Заголовки внутри вкладок попадают в оглавление статьи. Переход по такой ссылке, в том числе из другого окна, открывает нужную вкладку. Имена вкладок сами по себе не являются заголовками оглавления. Существующие блоки `quiz` по-прежнему размещайте на верхнем уровне статьи; примеры их синтаксиса внутри кода не выполняются.

## 16. Ссылка на конкретный заголовок

У заголовков `##`–`######` появляется значок ссылки при наведении или фокусе клавиатуры; на сенсорных устройствах он виден постоянно. Нажатие копирует полный адрес с якорем. Если браузер запрещает буфер обмена, откроется выделенная ссылка для ручного копирования. Без JavaScript значок работает как обычная ссылка на заголовок.

В скопированный адрес не включаются временные параметры `route` и `resume`. Названия заголовков и идентификаторы, используемые оглавлением, не меняются. Если переименовать заголовок, автоматически вычисляемый якорь может измениться. Для постоянной ссылки можно назначить идентификатор явно:

```md
## Подключение питания {#power-connection}
```

Ссылка на такой раздел заканчивается на `#power-connection` и сохранится при изменении текста заголовка.

## 17. Создание учебного маршрута

Маршрут объединяет существующие статьи в нужном порядке, в том числе из разных категорий. Создайте рядом с `main.py` папку `learning-paths/`, а внутри — файл, например `pico-start.md`. Для имени используйте буквы, цифры, дефис и подчёркивание, без пробелов и точек. Папка локальная и исключена из Git; сайт не создаёт готовые маршруты автоматически.

```text
learning-paths/
  pico-start.md
  printing-start.md
```

Минимальный маршрут:

```md
# Первые шаги с Pico

Для знакомства с платой и подключением периферии.

## Шаги

1. [Подготовка среды](/10-example/00-intro)
2. [Подключение дисплея](/10-example/01-oled#connections)
3. [Практическое задание](/20-practice/00-first-task)
```

**Адреса в примере условные:** замените их URL существующих статей, скопированными из браузера. Не используйте пути к `.md` на диске. Для перехода к определённому месту допустим якорь; он должен существовать в целевой статье. Параметры запроса в исходных ссылках шагов не нужны и не принимаются.

Первый `# Заголовок` задаёт название маршрута и не дублируется на странице. Введение до `## Шаги` может содержать обычный Markdown. Нужен ровно один раздел `## Шаги` с одним верхнеуровневым нумерованным списком. Первая ссылка каждого пункта задаёт статью, текст ссылки — название шага; после ссылки можно добавить пояснение. Ссылки во введении не считаются шагами. После списка можно разместить другие разделы.

Одна статья может входить в несколько маршрутов, но только один раз в каждом, даже если ссылки ведут к разным заголовкам этой статьи. Ошибочные и повторные шаги пропускаются. Маршрут без действительных шагов или с неверной структурой не публикуется; команда проверки сообщает причину. После исправления файл снова появится на сайте без перезапуска.

Список находится на `/paths`, отдельная страница — на `/paths/pico-start`. На главной появляется блок маршрутов перед категориями; без маршрутов он скрыт. Ссылка в футере остаётся доступной. Статьи показывают, в какие маршруты входят.

При открытии шага сайт добавляет `?route=pico-start` перед якорем. Над статьёй появляются название маршрута со ссылкой для возврата, номер шага и переходы к предыдущему и следующему шагам. На границах недоступный переход неактивен. Нижняя фиксированная панель продолжает переключать статьи по категории. Чтобы выйти из контекста маршрута, откройте статью без `route`.

Контекст сохраняется после ввода пароля и через продолжение чтения; закладки остаются обычными ссылками на статьи. Маршрут публичен: в его тексте нельзя размещать секретную информацию. Закрытые шаги отмечены словом «закрыто», при открытии проверяется пароль категории. Содержимое защищённых статей на страницу маршрута не копируется.

## 18. Проверка администратора перед публикацией

### Индикатор загрузки

При переходе по внутренней ссылке и обычной отправке формы сайт показывает кольцевой индикатор в цветах текущей темы только на исходной странице. На открываемой странице повторной заставки нет; при прямом открытии сайта она также не появляется. Индикатор появляется через 120 мс: при быстрых переходах заставка не мелькает. Проценты не показываются, поскольку браузер не сообщает достоверный общий прогресс загрузки.

Якоря на текущей странице, внешние ссылки, скачивания и формы, обрабатываемые JavaScript без перехода, индикатор не включают. При возврате кнопками браузера он сбрасывается. Анимация отключается при системной настройке уменьшения движения; клавиша `Esc` скрывает заставку.

На исходной странице действует страховочный тайм-аут в десять секунд для отменённых или зависших переходов. Он не отменяет запрос и не мешает дальнейшей загрузке ресурсов. Заставка не добавляет задержек к навигации и не заменяет оптимизацию сервера и изображений. Логика находится в `static/navigation.js`, оформление — в `static/style.css`; скрипт подключается через общий футер. Без JavaScript сайт работает без заставки.

Изображения показываются целиком после загрузки и декодирования, без постепенной прорисовки сверху вниз. Это относится к фотографиям, иллюстрациям в статьях и галерее, фоновым плиткам и угловым рисункам темы. Текст не ждёт загрузки картинок. Ошибки изображений не блокируют страницу; у обычных картинок остаётся альтернативный текст. Логика находится в `static/images.js`, раннее включение — в `static/theme.js`. Если скрипт изображений недоступен, через пять секунд возвращается обычное отображение; без JavaScript оно используется сразу.

### Контрольный список

1. Проверьте, что все новые файлы и картинки доступны пользователю сервиса.
2. Откройте изменённую статью и проверьте отступы блоков, обе вкладки, код и оглавление.
3. Откройте маршрут и пройдите все шаги, включая защищённые и находящиеся в других категориях.
4. Проверьте страницу на телефоне и в тёмном режиме.
5. Выполните автоматические проверки из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe tools/check_content.py
```

Для проверки другого набора материалов и маршрутов:

```powershell
.\.venv\Scripts\python.exe tools/check_content.py --articles C:\content\articles --paths C:\content\learning-paths
```

Утилита проверяет ссылки и якоря, изображения, вложения, термины, задания, авторов и шаги маршрутов. Она ничего не исправляет и не перезаписывает. Ошибки дают код завершения `1`, отсутствие ошибок — `0`; внешние сайты не опрашиваются. Если на главной нет блока маршрутов, сначала проверьте имя папки, расширение `.md`, заголовок `## Шаги` и сообщения этой команды.
